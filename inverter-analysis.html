HISTORICAL THRESHOLD ANALYSIS

Seasonal Threshold Lab

วิเคราะห์ Unit (%) รายวันย้อนหลังเพื่อช่วยประเมินเกณฑ์แจ้งเตือนรายโครงการและรายเดือน ระบบเสนอค่าเท่านั้นและจะไม่นำไปใช้โดยอัตโนมัติ เพื่อรองรับผลจากแนวทางดวงอาทิตย์ ทิศทางแผง การจำกัดกำลัง และเหตุผิดปกติจริงในอดีต

STEP 1เลือกโครงการเริ่มจากโครงการเดียวก่อน ระบบจะอ่าน Unit (%) ย้อนหลังของโครงการนั้น
STEP 2ดูค่าที่แนะนำค่าที่แนะนำคำนวณจากเปอร์เซ็นไทล์ย้อนหลัง และระบบจะไม่นำไปใช้โดยอัตโนมัติ
STEP 3เลือกรูปแบบเกณฑ์แจ้งเตือนตามฤดูกาล = ใช้เดือนเดียวกันทุกปี · เฉพาะปี = ตั้งค่าเฉพาะปีที่เลือก
STEP 4ตรวจสอบแล้วนำไปใช้กรอกค่าด้วยตนเองหรือเลือกค่าที่แนะนำ แล้วนำไปใช้ จากนั้นกลับไปหน้ารายวันเพื่อตรวจผลบนกราฟ

Analysis Controls

เลือกโครงการและวิธีคำนวณค่าฐานย้อนหลัง ระบบจะคำนวณ Unit (%) ใหม่จากข้อมูลดิบรายวันทุกครั้ง และใช้เฉพาะข้อมูลที่ผ่านเงื่อนไขปัจจุบัน

วิธีอ่านตัวควบคุมการวิเคราะห์
History Scope = เลือกว่าจะใช้ปีใดในการสร้างคำแนะนำ · P05 = ค่าช่วงล่าง 5% ของข้อมูล (ค่อนข้างผ่อนปรน), P10/P15 = การแจ้งเตือนไวขึ้น · Minimum valid days = จำนวนวันข้อมูลที่ใช้ได้ขั้นต่ำในปี/เดือนนั้นก่อนนำมาคำนวณค่าที่แนะนำ

Suggested Threshold Method: 1) แยก Unit (%) ตามปีและเดือน → 2) หาเปอร์เซ็นไทล์ของแต่ละปี → 3) ใช้ค่ามัธยฐานของค่ารายปีเป็นเกณฑ์แจ้งเตือนที่แนะนำ เพื่อลดผลกระทบจากปีที่มีความขัดข้องรุนแรงผิดปกติ
ค่าที่แนะนำไม่ใช่ค่าบังคับ — ต้องตรวจสอบก่อนนำไปใช้เสมอ
คู่มือเปอร์เซ็นไทล์ย้อนหลัง · Historical Percentile

แนวคิด: ระบบไม่ได้ใช้ค่าเฉลี่ยของ Unit (%) แต่ดู “ค่าช่วงล่าง” ของข้อมูลในเดือนเดียวกันของแต่ละปี เพื่อหาเกณฑ์ที่สะท้อนพฤติกรรมจริงของโครงการ

P05 = มีประมาณ 5% ของค่าที่ต่ำกว่าค่านี้ → ผ่อนปรนกว่า เหมาะเป็นจุดเริ่มต้นเมื่อไม่ต้องการ Alarm เยอะเกินไป
P10 = มีประมาณ 10% ของค่าที่ต่ำกว่าค่านี้ → ไวขึ้น เหมาะเมื่ออยากจับการลดลงให้เร็วขึ้น
P15 = มีประมาณ 15% ของค่าที่ต่ำกว่าค่านี้ → ไวมากขึ้น แต่อาจเกิด Alarm จากความแปรปรวนปกติมากขึ้น

วิธีคำนวณ Suggested Threshold: 1) แยก Unit (%) ตาม Project + เดือน + ปี → 2) หา P05/P10/P15 ของแต่ละปี → 3) ตัดปี/เดือนที่มี Valid Days ต่ำกว่า Minimum valid days → 4) นำค่า Percentile ของปีที่ผ่านมาหา Median → ได้ Suggested Threshold ของเดือนนั้น

ตัวอย่าง: Sep 2023 = P05 91.8%, Sep 2024 = 93.1%, Sep 2025 = 92.4% → Suggested Sep = Median = 92.4%

Confidence: High = ≥3 ปีและรวม ≥45 valid days · Medium = ≥2 ปีและรวม ≥20 valid days · Low = มีเพียง ≥1 ปีที่ใช้ได้

คำแนะนำใช้งาน: เริ่มจาก P05 → ตรวจ False Alarm ในหน้า Daily → ถ้าหลุดความผิดปกติมากเกินไปค่อยเพิ่มเป็น P10/P15. ค่า Suggested เป็นคำแนะนำเท่านั้น ไม่ควร Apply ทุกเดือนอัตโนมัติ โดยเฉพาะเดือนที่มี Power Limit, Shutdown, GI ผิดปกติ หรือโครงสร้าง/Capacity เปลี่ยน

Settings & Calculation Guide

รวมสมการประสิทธิภาพรายวัน ความพร้อมใช้งานรายเดือน ตัวเลือกเงื่อนไข ระยะเวลาอ้างอิง และขั้นตอนการวิเคราะห์รายเดือนไว้ที่นี่ โดยไม่รบกวนหน้าภาพรวม

Daily Relative Performance

ระบบคำนวณใหม่ตอนนำเข้า และไม่ใช้ Unit (%) เดิมเป็นแหล่งข้อมูลหลัก

Unit (%) = Specific Energyᵢ ÷ Max Specific Energy(Project, Date) × 100

เมื่อ วันที่ + โครงการ + อุปกรณ์ มีหลายรายการ ระบบใช้ Min of Unit (%) ให้เหมือนพฤติกรรมของตารางสรุปเดิม

  • เมื่อพลังงานจำเพาะ = 0 ระบบจะตรวจระยะเวลาเชื่อมต่อกริดก่อนจัดประเภท
  • ไม่มีข้อมูลจะแสดงเป็นช่องว่าง ไม่ใช่ 0%
  • อินเวอร์เตอร์ที่ถูกยกเว้นยังแสดงบนกราฟ แต่ไม่ใช้สร้างค่าพลังงานจำเพาะสูงสุดอ้างอิง

Monthly Relative Availability

ระยะเวลาอ้างอิงคำนวณแยกตามโครงการและเดือน และห้ามนำค่าอ้างอิงรายวันมาใช้กับรายเดือน

Availability = min(Grid Connection Duration ÷ Reference Duration × 100, 100)
Lost Hours = max(Reference Duration − Grid Connection Duration, 0)

วิธีหาค่าอ้างอิงรองรับ P95 / ค่าสูงสุด / มัธยฐาน / กำหนดเอง โดย P95 เป็นค่าเริ่มต้น · ค่าที่กำหนดเองบันทึกแยกตามโครงการ + เดือน และหากยังไม่กรอก ระบบจะใช้ P95 สำรองพร้อมแจ้งเตือน

Monthly Reference Method

Page-by-page User Guide

คู่มือนี้อธิบายว่าควรใช้แต่ละหน้าเมื่อใด และควรตรวจอะไรเป็นอันดับแรก

1. ภาพรวม · เริ่มจากหน้านี้

ใช้ดูภาพรวมพอร์ตโฟลิโอก่อนลงรายละเอียด

  • โหมดรายเดือน: ความพร้อมใช้งาน / ชั่วโมงสูญเสีย / โครงการที่ต้องตรวจ
  • โหมดรายวัน: ประสิทธิภาพสัมพัทธ์ / การแจ้งเตือนของอินเวอร์เตอร์
  • หากต้องการหาความผิดปกติรายวัน → ประสิทธิภาพรายวัน

2. Daily · Relative Performance Trend

ใช้ตอบคำถามว่า “อินเวอร์เตอร์ตัวใดผลิตต่ำกว่าตัวอื่นในโครงการเดียวกัน”

  • Unit (%) = พลังงานจำเพาะของตัวนั้น ÷ พลังงานจำเพาะสูงสุดของวัน
  • เส้น/จุดที่ต่ำกว่าเกณฑ์เป็นการแจ้งเตือนเชิงภาพ และสามารถเปิด/ปิดได้
  • รายละเอียดอินเวอร์เตอร์รายวันด้านล่างใช้ตรวจค่ารายวันและความคิดเห็น

3. Monthly · Relative Availability

ใช้ดูระยะเวลาที่อินเวอร์เตอร์เชื่อมต่อกริดเทียบกับค่าอ้างอิงของโครงการ

  • ความพร้อมใช้งานโครงการ = สรุประดับโครงการ
  • ความพร้อมใช้งานต่ำสุด = รายการที่ควรตรวจ
  • รายละเอียดอินเวอร์เตอร์ = ค่ารายอินเวอร์เตอร์ + สาเหตุ / หมายเหตุสำหรับรายงาน

4. ห้องทดลองเกณฑ์แจ้งเตือน · ใช้เมื่อเกณฑ์ 95% ไม่เหมาะกับทุกเดือน

ห้องทดลองเกณฑ์แจ้งเตือนไม่ได้หาค่า “ดีที่สุด” โดยอัตโนมัติ แต่ช่วยเสนอค่าจากข้อมูลย้อนหลังเพื่อให้ผู้ใช้ตัดสินใจ

  • เลือกโครงการ
  • ดูเกณฑ์แจ้งเตือนที่แนะนำรายเดือน
  • ดูระดับความเชื่อมั่นและจำนวนวันที่ใช้ได้
  • เลือกแบบตามฤดูกาลหรือเฉพาะปี
  • นำไปใช้แล้วกลับไปหน้ารายวัน เพื่อตรวจว่ามีการแจ้งเตือนผิดมากหรือน้อยเกินไปหรือไม่
  • การเปรียบเทียบข้ามปีถูกปิดชั่วคราว เพราะยังไม่จำเป็นต่อขั้นตอนหลัก

  • เลือกรายวัน / รายเดือน / ทั้งสองแบบ
  • เลือกขอบเขต

ขั้นตอนย่อของห้องทดลองเกณฑ์แจ้งเตือน: หากยังไม่แน่ใจ ให้เริ่มจากค่าเริ่มต้น 95% → เลือกโครงการ → ดูค่าที่แนะนำรายเดือน → นำไปใช้เฉพาะเดือนที่มีความเชื่อมั่นดีและข้อมูลเพียงพอ → กลับไปหน้ารายวันเพื่อตรวจผลจริง อย่านำค่าที่แนะนำทั้งหมดไปใช้โดยไม่ตรวจสอบ

Historical Percentile · คู่มือเลือก P05 / P10 / P15

เปอร์เซ็นไทล์ย้อนหลังใช้เพื่อสร้าง Suggested Threshold ราย Project + Month จาก Daily Unit (%) โดยไม่ Apply ค่าให้อัตโนมัติ

Suggested(Month) = Median( Percentile(Unit % ของเดือนนั้นในแต่ละปี) )
  • P05: Conservative · Alarm น้อยกว่า เหมาะเป็นค่าเริ่มต้น
  • P10: Balanced / Sensitive มากขึ้น
  • P15: Sensitive สูง · ควรตรวจ False Alarm มากขึ้น
  • Minimum valid days: ปี/เดือนที่ข้อมูลไม่ถึงจำนวนวันที่กำหนดจะไม่ถูกใช้
  • History Scope: Previous years only เหมาะเป็น Default เพื่อไม่ให้ปีที่กำลังตรวจมีผลต่อ Threshold ของตัวเอง
  • Confidence: High ≥3 ปี & ≥45 วัน, Medium ≥2 ปี & ≥20 วัน, Low ≥1 ปี

ตัวอย่าง: P05 ของ Sep = 91.8, 93.1, 92.4 → Suggested = 92.4%. หลัง Apply ต้องกลับไปหน้า Daily ตรวจจำนวน Alarm และเหตุการณ์จริงเสมอ
