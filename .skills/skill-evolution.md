# Skill Evolution

Continuously improve project skills from real usage patterns.

## When to evolve a skill
Promote a repeated pattern into a rule when it:
- Appears repeatedly across tasks.
- Prevents recurring bugs or rework.
- Saves meaningful reads/tool calls/credits.
- Protects important business logic or data.
- Creates a reusable testing or implementation pattern.

## Evolution workflow
1. Observe repeated friction or repeated successful behavior.
2. Verify the pattern is stable, not a one-off exception.
3. Add or refine the narrowest relevant skill.
4. Update AGENTS.md only when routing genuinely improves.
5. Keep rules concise and avoid duplication.
6. Preserve validated project-specific constraints.
7. Update WORKFLOW-NOTE.md only when the change helps the user understand the workflow.

## Do not overfit
Do not create a new skill for every request.
Prefer extending an existing skill when the new rule belongs to the same domain.
Simplify or remove obsolete guidance as the system grows.
